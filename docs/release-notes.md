# Keeppeer v1 — local candidate notes

Confirmed version 1.0 (code 1), applicationId `com.gem.keeppeer`, API24+. Confirmed no prior distribution (no Play Store, sideload, or beta). GitHub repository source upload is planned; that is not app distribution and does not affect versionCode. This is a local review candidate, not a published release. Current engineering outcome and exact gates are in [the Phase5 report](reports/phase-5-report.json).

V1 provides an on-device encrypted vault with exact-value entry CRUD/search, favorites/category filters, masked reveal, a SecureRandom password generator, ownership-aware sensitive clipboard copies, master-password setup/unlock/change, optional per-use Keystore biometric unlock with password fallback, immediate/1/5-minute background timeout choices, persisted System/Light/Dark appearance, and plaintext CSV backup/restore through Android SAF. There is no account, sync, analytics, network permission, attachment/sharing feature or browser autofill.

Phase5 prepares deliberate local release opt-in, whole-app R8/resource shrinking, an unsigned production candidate and separately labelled non-debuggable development-signed validation. Production signing is a separate explicit opt-in using private local configuration; no production identity was created/selected/used. Default Android launcher artwork is replaced by a project lock vector. Minified builds safely refuse legacy Phase1 plaintext evidence without reset/deletion. A demonstrated API24 Settings/IME window-position defect is corrected using the documented full-screen Dialog inset configuration. No schema, encryption/KDF/envelope or dependency/toolchain upgrade occurred.

A forgotten master password or lost device-bound keys may permanently prevent access. Automatic backup/transfer is disabled. Before device loss/transfer, a user-selected CSV copy is the supported separate backup path; it contains plaintext passwords and the provider can be remote. Protect it separately. Credential spaces, multiline Unicode and formula-like strings are retained; spreadsheet quoting does not prevent formula interpretation, and optional empty/null values have the documented CSV behavior. See [security](security.md) and [CSV contract](csv-contract.md).

Keystore/biometrics, clipboard access/keyboard histories, secure-window capture policy and external document providers have platform/OEM limits. Packaged ABI/alignment checks do not establish every ABI/device or16KiB runtime. Actual tested environments and unobserved hardware/manual cases are reported individually. Required missing verification and pending production signing prevent a production-release-ready claim. No build has been published, uploaded or distributed by this task.
